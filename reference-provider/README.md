# OIDC Reference Provider (test-only)

This application is a deliberately small HTTPS host for exercising the
[`darkside/openid-connect-server` Packagist package](https://packagist.org/packages/darkside/openid-connect-server)
without depending on any other production application or local library checkout.

**It is a test fixture, not a production OpenID Provider. Do not expose it to real users, use real
accounts, or use production signing keys.** Its default static client, single test identity,
file-backed repositories and deliberately limited login flow exist only to make the library
independently runnable and suitable for protocol/interoperability experiments. Optional test-only
dynamic registration can create additional clients when an initial access token is configured.

## What it exercises

- `/.well-known/openid-configuration` — metadata generated by the library.
- `/authorize` — League Authorization Code validation, PKCE S256 and required nonce, with a small
test-only login/approval form.
- `/token` — League token endpoint and the library's ID Token response extension.
- `/jwks` — RS256 public signing key publication.
- `/userinfo` — the library's Bearer-token-protected UserInfo handler.
- `/logout` — RP-Initiated Logout with ID Token hint validation, CSRF-protected confirmation,
  session binding and exact post-logout redirect allowlisting.
- Optional Back-Channel Logout delivery to the configured RP HTTPS callback. The endpoint is
  advertised only when `OIDC_REFERENCE_BACKCHANNEL_LOGOUT_URI` is configured.
- Optional client creation at `/register`, advertised only when
  `OIDC_REFERENCE_REGISTRATION_INITIAL_ACCESS_TOKEN` is configured. The example accepts only web
  clients using the authorization-code grant and `client_secret_basic`; generated secrets are
  returned once and stored as password hashes.
- `offline_access` — rotating refresh tokens, explicit consent (`prompt=consent`), single-use
  refresh-token consumption and family revocation after reuse.
- File-backed nonce metadata with atomic one-time consumption under a file lock.
- File-backed access-token, authorization-code and refresh-token state.

The advertised profile is `authorization_code` / `code` with the `refresh_token` grant enabled for
the test client. It uses `query` response mode, PKCE `S256`, RS256 ID Tokens and
`client_secret_basic`. The only registered client and user are local test fixtures.

## Requirements

- PHP 8.2+ with `openssl`, `json` and `fileinfo` extensions.
- Composer.
- Apache with `mod_rewrite` and `mod_ssl` for the documented WAMP setup, or another HTTPS-capable web server.

## Install and initialize (Windows CMD or a terminal)

From this directory:

```cmd
composer install
php bin/setup.php
```

The setup command generates separate OAuth and OIDC RSA key pairs, an OAuth encryption key, and a
local `.env` file containing random test credentials. It does not overwrite existing keys or an
existing `.env`. Keep `.env` and `var/` private and out of version control.

Review `.env`. For local testing it defaults to:

```text
OIDC_REFERENCE_BASE_URL=https://oidc-reference.loc
OIDC_REFERENCE_CLIENT_ID=oidc-test-client
OIDC_REFERENCE_REDIRECT_URI=https://oidc-client.loc/callback
```

The client secret and test-user password are generated and printed once by `bin/setup.php`; they
are also stored in `.env` for local use. The test login username defaults to `alice`.

## Run locally with WAMP Apache (Windows)

The provider's public document root is `reference-provider/public`. The included `public/.htaccess`
rewrites endpoint paths to `index.php`; Apache must have `mod_rewrite` enabled and `AllowOverride All`
for this directory.

Add this entry to the Windows hosts file (run Notepad as Administrator):

`C:\Windows\System32\drivers\etc\hosts`

```text
127.0.0.1 oidc-reference.loc
```

Configure an HTTPS VirtualHost in WAMP Apache, using your actual certificate and key paths:

```apache
<VirtualHost *:443>
    ServerName oidc-reference.loc
    DocumentRoot "C:/path/to/openid-connect-server-examples/reference-provider/public"

    SSLEngine on
    SSLCertificateFile "C:/path/to/certificate-with-oidc-reference.loc-SAN.crt"
    SSLCertificateKeyFile "C:/path/to/certificate.key"

    <Directory "C:/path/to/openid-connect-server-examples/reference-provider/public">
        Options FollowSymLinks
        AllowOverride All
        Require local
    </Directory>

    ErrorLog "logs/oidc-reference-error.log"
    CustomLog "logs/oidc-reference-access.log" combined
</VirtualHost>
```

Ensure `ssl_module` and `rewrite_module` are enabled, and that the certificate SAN includes
`oidc-reference.loc`. Restart Apache after changing the VirtualHost. Do not set the document root to
the `reference-provider` directory itself: `.env`, `var/`, private keys and source code must remain
outside the web root.

Set the `.env` origin to exactly `https://oidc-reference.loc`. The discovery issuer must match this
value exactly.

Check:

- `https://oidc-reference.loc/health`
- `https://oidc-reference.loc/.well-known/openid-configuration`
- `https://oidc-reference.loc/jwks`

A Caddyfile is retained as an optional alternative for users who are not using Apache; Caddy is not
required when WAMP Apache serves the HTTPS VirtualHost directly.

## Test client configuration

The sibling [`interop-client/`](../interop-client/README.md) is preconfigured to use the reference client profile. Its redirect URI must match `OIDC_REFERENCE_REDIRECT_URI`. The browser-based RP flow requires an HTTPS virtual host for the RP callback. The command-line security probes process redirects themselves and do not require a separate callback listener.

Do not weaken redirect URI validation to accommodate a client callback.

## Automated tests

From this directory:

```cmd
vendor\bin\phpunit
vendor\bin\phpstan analyse
vendor\bin\php-cs-fixer fix --dry-run --diff
```

The reference-provider test suite is separate from the root library suite because it has its own
Composer dependencies and runtime. Run both suites before changing the library or reference host.

## Independent RP interoperability

Use the sibling [`interop-client/`](../interop-client/README.md) project for the local independent
client flow. It uses a separate Composer project and a different hostname so the provider and RP
are exercised as distinct HTTP applications.

## Explicit limitations

- This is not a production server and has no user database, password hashing, MFA, real consent
  management, account lifecycle, client-management UI, rate limiting, audit pipeline or operational
  key-rotation service.
- The file-backed reference repositories are designed for a local single-worker test fixture.
  They are not a substitute for a production database implementation with transactionally atomic
  authorization-code redemption and distributed revocation.
- The reference app does not implement features outside the library's current advertised profile.
- A successful local smoke test or the library's own PHPUnit suite is not OIDC certification.
  Independent relying-party interoperability is exercised by the sibling `interop-client/` project.
  OpenID Foundation conformance testing is an optional future activity.


## Test-only token security configuration

For Phase 6D.2 local security tests, configure `OIDC_REFERENCE_ACCESS_TOKEN_TTL_SECONDS=5` and a long random `OIDC_REFERENCE_TEST_CONTROL_SECRET` in `.env`, then restart Apache. The revocation control route is test-only and is disabled (404) unless that secret is configured. Never enable it in a deployed provider.

The active OIDC signing key can be selected with `OIDC_REFERENCE_OIDC_KEY_ID`, `OIDC_REFERENCE_OIDC_PRIVATE_KEY_PATH`, and `OIDC_REFERENCE_OIDC_PUBLIC_KEY_PATH`. Retired public verification keys can be retained in JWKS using `OIDC_REFERENCE_RETIRED_OIDC_KEYS`, formatted as semicolon-separated `kid=public-key-path` entries. Generate a fresh key pair with `php bin/generate-oidc-rotation-key.php <new-key-id>`. Keep retired public keys available until tokens signed with them have expired; private keys must never be published.

## Phase 6D.3 signing-key rotation test

See [`../docs/PHASE-6D3-KEY-ROTATION.md`](../docs/PHASE-6D3-KEY-ROTATION.md) for the complete two-stage
procedure. In brief, generate a new RSA pair with `php bin/generate-oidc-rotation-key.php <new-kid>`,
configure it as the active key using `OIDC_REFERENCE_OIDC_KEY_ID` and the active key paths, and retain
the previous **public** key in `OIDC_REFERENCE_RETIRED_OIDC_KEYS`. Never configure or publish a retired
private key. The optional `OIDC_REFERENCE_ID_TOKEN_TTL_SECONDS` setting controls the test fixture's
ID Token lifetime (1–3600 seconds; default 300 seconds) to give the manual rotation test enough time.
